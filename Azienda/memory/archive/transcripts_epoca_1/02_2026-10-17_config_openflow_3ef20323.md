### Cosa puoi configurare stasera senza modello agganciato

Puoi preparare quasi l'intera infrastruttura di OpenClaw. Ecco i passaggi consigliati:

---

#### 1. Diagnostica iniziale e verifica installazione
Verifica che l'installazione sia integra e che non manchino dipendenze di sistema:
```bash
openclaw doctor
```
Se segnala problemi o configurazioni mancanti, puoi eseguire `openclaw doctor --fix` per risolverli automaticamente.

---

#### 2. Inizializzazione della cartella di configurazione e Workspace
Se non lo hai già fatto, avvia il setup guidato:
```bash
openclaw onboard
```
Oppure crea direttamente la struttura base in `~/.openclaw`:
- **File di configurazione:** `~/.openclaw/openclaw.json` (o `.json5`)
- **Cartella Workspace:** `~/.openclaw/workspace` (qui OpenClaw salverà memorie, prompt personalizzati e file di sessione)

---

#### 3. Configurazione dei canali di comunicazione (es. Telegram o Discord)
Questa è la parte più comoda da configurare in anticipo:

##### Esempio Telegram:
1. Apri Telegram e cerca **`@BotFather`**.
2. Invia `/newbot`, assegna un nome e ottieni il **Bot Token** (es. `123456:ABC-DEF...`).
3. Recupera il tuo ID utente Telegram (puoi scoprirlo scrivendo a bot come `@userinfobot`).
4. Inserisci il canale in `~/.openclaw/openclaw.json` con la whitelist di sicurezza (`allowFrom`) per evitare che sconosciuti usino il tuo assistente:
```json5
{
  "channels": {
    "telegram": {
      "botToken": "IL_TUO_BOT_TOKEN_TELEGRAM",
      "allowFrom": ["IL_TUO_TELEGRAM_USER_ID"]
    }
  }
}
```

---

#### 4. Predisposizione del file di sicurezza per le chiavi API
Prepara il file per le credenziali con permessi di lettura ristretti solo al tuo utente:
```bash
touch ~/.openclaw/.env
chmod 600 ~/.openclaw/.env
```
Quando prenderai l'API key (anche gratuita da Google AI Studio), basterà aggiungerla dentro:
```bash
echo 'GEMINI_API_KEY="la-tua-api-key-qui"' >> ~/.openclaw/.env
```

---

### Quando collegherai Gemini (anche stasera gratis da AI Studio)

Basterà aggiungere nel tuo `~/.openclaw/openclaw.json`:
```json5
{
  "models": {
    "providers": {
      "google": {
        "apiKey": "${GEMINI_API_KEY}"
      }
    },
    "defaults": {
      "provider": "google",
      "model": "gemini-2.5-flash"
    }
  }
}
```
E avviare il gateway:
```bash
openclaw gateway restart
openclaw gateway status
```

### Il motivo del problema

Il problema è un **conflitto di versioni**:

1. **L'applicazione Mac** che hai scaricato (`/Applications/OpenClaw.app`) è la versione più recente: **`2026.10.4`**. È stata lei a generare la configurazione (`openclaw.json`) e il database SQLite (che usa lo schema moderno versione 20).
2. L'installazione da `npm` (`npm install -g openclaw`) ha invece installato una **vecchia versione (`2026.6.35`)** nel percorso di NVM.
3. Quando lanciavi `openclaw` da terminale, partiva la versione vecchia, che:
   - Non riconosceva lo schema del database: `uses newer schema version 20; this OpenClaw build supports 1`
   - Non riconosceva le chiavi introdotte nella versione di ottobre: `meta.migrations` e `agents.defaults.utilityModel`
   - Segnalava la configurazione come non valida per errore.

---

### Come risolvere in 2 passaggi

Esegui questi comandi nel tuo terminale:

#### 1. Rimuovi la vecchia versione installata con npm
```bash
npm uninstall -g openclaw
```

#### 2. Collega il comando `openclaw` al motore aggiornato (`2026.10.4`) integrato nell'App
Crea il wrapper eseguibile nella tua cartella `~/.local/bin` (che è già configurata nel tuo `$PATH`):

```bash

#!/usr/bin/env bash
exec /Applications/OpenClaw.app/Contents/Resources/runtime/bin/bun /Applications/OpenClaw.app/Contents/Resources/runtime/lib/node_modules/openclaw/openclaw.mjs "$@"
EOF
chmod +x ~/.local/bin/openclaw
```
